# 자산평가 현황 관리 대시보드

코람코자산운용 펀드관리팀용 자산평가 현황 대시보드. Google Sheets를 DB로, GitHub Pages로 호스팅하는 순수 HTML/CSS/JS 웹앱.

## 폴더 구조

```
webapp/
  index.html            메인 페이지
  css/style.css          스타일
  js/
    config.js            설정값 (배포 전 필수 수정)
    utils.js              CSV 파싱, 날짜/통화 포맷, 배지 등 유틸
    api.js                 Sheets 읽기(CSV export) / Apps Script 쓰기
    dashboard.js            대시보드 뷰 (KPI, 자산 테이블, 정렬/검색/엑셀 다운로드)
    panel.js                우측 사이드패널 (펀드 상세/보유자산/관리자 입력)
    history.js               평가이력 타임라인 뷰
    committee.js               위원회 개최이력 뷰
    admin.js                  관리자 모드 (로그인, CSV 업로드, 평가방법 관리, 이력 입력)
    main.js                    전체 오케스트레이션
  apps-script/Code.gs        Google Apps Script 백엔드 (쓰기 전용 API)
  data/                        참고용 CSV 원본 (Sheets에 최초 업로드할 데이터)
```

## 1. Google Sheets 준비

1. 새 스프레드시트를 만들고 시트 탭 5개를 아래 이름으로 생성: `fund_master`, `asset_detail`, `eval_history`, `committee_history`, `config`
2. `data/` 폴더의 CSV 5개를 각각 동일한 이름의 시트에 가져오기(파일 > 가져오기 > 현재 시트 바꾸기)
   - `committee_history.csv`에는 fund_master의 의결일(prev_dt)과 config의 대체평가의결일 데이터를 근거로 추정한 위원회 개최이력 1건이 미리 채워져 있습니다. 실제 회의록을 기준으로 회차·안건·참석위원·의결내용을 확인 후 수정해 주세요.
3. 스프레드시트 공유 설정을 **"링크가 있는 모든 사용자 - 뷰어"** 로 변경 (읽기를 CSV export 공개 링크 방식으로 처리하기 때문에 필수)
4. 주소창에서 스프레드시트 ID 확인: `https://docs.google.com/spreadsheets/d/이 부분이 ID/edit`

## 2. Apps Script 배포 (쓰기 API)

1. 스프레드시트 열기 → 확장 프로그램 → Apps Script
2. 기본 코드를 지우고 `apps-script/Code.gs` 내용을 붙여넣기
3. 왼쪽 톱니바퀴(프로젝트 설정) → 스크립트 속성 → 속성 추가
   - 속성: `WRITE_TOKEN`, 값: 임의의 긴 문자열 (예: openssl로 생성한 랜덤 문자열)
4. 배포 → 새 배포 → 유형 선택(웹앱)
   - 설명: 아무거나
   - 실행 계정: 나
   - 액세스 권한: 전체
5. 배포 후 발급되는 URL(`.../exec`로 끝남)을 복사

## 3. config.js 값 채우기

`js/config.js`에서 아래 3개 값을 실제 값으로 교체:

```js
SPREADSHEET_ID: '실제 스프레드시트 ID',
APPS_SCRIPT_URL: '실제 Apps Script 웹앱 URL (…/exec)',
WRITE_TOKEN: 'Apps Script 스크립트 속성에 등록한 것과 동일한 문자열',
```

그리고 `ADMIN_PASSWORD` 값을 팀에서 사용할 비밀번호로 변경.

> 참고: 관리자 인증은 브라우저 단에서 비밀번호를 비교하는 간단한 방식이며(소스를 열람하면 비밀번호 문자열이 노출될 수 있음), 쓰기 요청은 `WRITE_TOKEN`으로 서버(Apps Script)에서 한 번 더 검증합니다. 내부 팀 4명이 함께 쓰는 용도로는 충분하지만, 더 엄격한 통제가 필요하면 Apps Script 쪽에 Google 계정 기반 인증을 추가하는 것을 권장합니다.

## 4. GitHub Pages 배포

1. GitHub 저장소 생성 (또는 기존 저장소 사용)
2. `webapp/` 폴더 내용을 저장소 루트(또는 `/docs` 폴더)에 push
3. 저장소 Settings → Pages → Source에서 브랜치/폴더 지정 후 저장
4. 발급된 URL로 접속하여 데이터가 정상적으로 로드되는지 확인

## 5. 기능 요약

- **대시보드**: KPI 4종(전체 펀드/비시장성 자산개수/외부평가 대상 자산/기한임박 자산), 오늘·기준일 배지, 검색·상태 필터, 정렬 가능한 자산 단위 테이블, CSV(엑셀) 다운로드
- **사이드패널**: 펀드 클릭 시 펀드 상세·보유자산 목록 표시. 관리자 모드에서는 펀드 정보·자산 평가 정보 수정 폼 노출
  - 보유자산의 "평가금액"을 입력하고 저장하면 **평가이력(eval_history)에도 자동으로 반영**됩니다. 같은 자산·같은 평가기준일(최근평가일)의 이력이 이미 있으면 그 행을 갱신하고, 없으면 새 이력 행을 추가합니다(장부가 반영여부는 일단 공란으로 생성되며, 실제 장부가 반영을 확인한 뒤 평가이력 탭에서 Y/N으로 전환해 주세요).
- **평가이력 탭**: 펀드·자산별 평가이력을 연도별로 표시합니다. 필드는 평가기준일(eval_base_date, 외부평가=감평보고서 상 평가기준일 / 대체평가=대체평가 의결일 / 부실·특정이벤트로 인한 위원회 개최=위원회 의결일)·평가금액·장부가 반영여부(Y=반영 / N=미반영 / 공란=확인필요)·특이사항으로 단순화되어 있습니다. 관리자 모드에서는 각 이력 항목의 **"수정" 버튼**으로 과거에 입력된 이력을 직접 고쳐 쓸 수 있습니다.
- **위원회 이력 탭**: 집합투자재산평가위원회 개최이력(회차·개최일·안건·대상펀드·의결내용·참석위원)을 최신순으로 표시. 각 이력에는 "평가시행 여부", "장부가 반영여부(Y=반영 / N=미반영 / 공란=확인필요)"와 "부실분류 여부/단계(부실우려·발생·개선·악화)"가 함께 표시됩니다. 관리자 모드에서는 장부가 반영여부를 드롭다운으로 바로 전환할 수 있습니다.
  - **평가시행 여부(eval_conducted)**: Y(평가시행)면 이 위원회 개최일이 대상 자산(들)의 평가기준일이 되고, 함께 입력한 평가금액이 대상 펀드×자산 조합 전체에 동일하게 적용되어 `eval_history`에도 자동으로 반영됩니다(보유자산 평가금액 저장 시 자동 반영되는 것과 동일한 방식 - 기존 이력이 있으면 갱신, 없으면 새로 추가). N(평가미시행)이면 절차적 의결일 뿐 평가금액이 없는 건이라 eval_history에는 반영하지 않습니다.
  - 부실분류는 반드시 평가위원회 의결을 통해서만 이루어진다는 원칙에 따라, 부실분류 여부·단계는 위원회 이력 입력폼에서만 기록합니다. 다만 실제 펀드/자산의 부실분류 필드 반영은 다른 항목과 동일하게 항상 자산 대시보드의 관리자 입력을 통해서만 이루어지며, 위원회 이력에서 자동으로 반영되지 않습니다. (위원회 이력은 "의결 기록", 자산 대시보드는 "실제 반영"이라는 역할 분리)
  - 보유자산 상세에서 자산명이 위원회 이력의 대상 자산(target_assets)과 일치하거나(또는 target_assets가 비어있으면 안건명에 자산명이 포함되면) "평가위원회 개최내역 보기" 버튼이 노출되어 관련 이력을 바로 확인할 수 있습니다.
- **관리자 모드**: 사이드바에서 비밀번호로 잠금 해제 → 월간 데이터 반영, CSV 일괄 업로드, 대체평가 방법 일괄 관리(자산 단위, 펀드코드 검색 지원), 외부평가 이력 입력·수정, 위원회 개최이력 입력 폼 사용 가능
  - 평가이력/위원회 이력 입력폼 모두, 펀드(코드)를 먼저 선택/입력하면 그 펀드가 보유한 자산명 목록에서 선택할 수 있습니다(평가이력은 드롭다운, 위원회 이력은 다중 입력 특성상 자동완성 목록).
  - **월간 데이터 반영**: 이번 달 펀드현황(펀드정보3)·자산현황(명세부) xlsx 두 개를 올리면, 현재 fund_master/asset_detail 시트와 비교해 변경/신규설정/상환처리/신규취득/매각추정/listed 확인필요 내역을 미리보기로 보여줍니다. 클래스펀드(종류형구분≠일반펀드/운용펀드)는 자동 제외되고, 기존 펀드의 fund_name(축약명)·eval_status(한 번 정해지면 유지)는 덮어쓰지 않습니다. 검토 후 "반영하기"를 눌러야만 실제 시트에 bulk_upload로 반영됩니다. 자세한 규칙은 [월간_데이터반영_절차.md](../월간_데이터반영_절차.md)와 [scripts/monthly_update.py](../scripts/monthly_update.py) 참고(두 구현은 로직이 동일해야 함).

## 6. 검증 방법

`test/smoke_test.js` (별도 제공)는 실제 CSV 데이터를 기반으로 KPI 계산, 테이블 렌더링, 검색 필터, 사이드패널, 관리자 모드, 평가이력 타임라인/수정, 위원회 이력, 보유자산→평가이력 자동 반영 등 25개 항목을 자동 검증합니다. Node.js + jsdom 환경에서 `node smoke_test.js`로 실행 가능(로컬 개발 확인용, 배포에는 불필요).

## 7. 알려진 제한사항 / 후속 작업 제안

- CSV export 방식은 공개 링크 기반이라 별도 인증 없이 시트 데이터를 읽을 수 있습니다. 민감도가 높다면 Sheets API v4 + API 키 또는 비공개 프록시 서버 방식으로 전환을 고려하세요.
- 반영의무여부 자동 계산은 화면 표시용이며, 시트에 이미 저장된 값(`Y`/`N`/`확인필요`)이 있으면 그 값을 우선 표시합니다.
- 동시 편집 충돌 처리(예: 두 명이 같은 펀드를 동시에 수정)는 별도로 구현되어 있지 않습니다.
- 위원회 이력의 "대상 펀드"는 펀드코드를 콤마로 구분한 텍스트로 저장됩니다(자동완성만 지원, 다중 선택 UI 아님). 향후 필요시 체크박스형 다중 선택으로 개선 가능합니다.
- 평가이력 행 수정/자동반영은 `fund_code + asset_name + eval_base_date(평가기준일)` 조합으로 대상 행을 찾습니다. 같은 자산에 대해 평가기준일까지 동일한 행이 두 개 이상 존재하는 극히 드문 경우, 그 중 첫 번째 행이 수정 대상이 될 수 있습니다.
- eval_history/committee_history 시트의 날짜 컬럼을 "날짜" 형식(Date)으로 입력해도 Apps Script에서 자동으로 `yyyy-MM-dd` 문자열로 변환해 비교하므로 텍스트/날짜 형식 어느 쪽이든 매칭에 문제가 없습니다.
- `committee_history`는 신규 시트이므로 fund_master/eval_history와 자동으로 연동(동기화)되지는 않습니다. 위원회에서 대체평가·적용기간을 새로 의결하면, 위원회 이력 입력과는 별개로 fund_master의 해당 값도 관리자 모드에서 함께 갱신해 주세요.
- **`committee_history` 시트에 `eval_conducted`, `eval_amount` 컬럼을 헤더(1행)에 직접 추가해야 합니다.** Apps Script는 시트 헤더에 있는 컬럼명만 매칭해서 쓰기 때문에, 이 두 컬럼이 없으면 관리자 모드에서 평가시행 여부/평가금액을 입력해도 저장되지 않습니다.
